- Existing More/Profile/Info layouts now expose support/privacy/about and deletion information. Deletion requires confirmation before opening email, explains the missing automatic flow and never claims completion.
- `docs/privacy-policy.ar.md`: implementation-based Arabic draft with unresolved owner/legal decisions. No hosted legal document was edited. `docs/account-deletion.ar.md`: public-facing content prepared for later hosting, not an existing deletion URL. Trusted cleanup requirements: `docs/account-deletion-operations.md`.
- `src/lib/network.ts`: 15-second deadline for standalone server reads only. The SDK operation may finish internally afterward; its result is not reused as a new success and no write is timed out by this wrapper. Queries retry only recognized transient errors once; permission/expired-session errors do not retry automatically. No mutation retry policy or offline outbox was added.
- Form failures preserve values and never navigate to success; submissions already have stable idempotency identifiers. Admin actions retain existing locks/transactions/confirmation; no app-driven automatic destructive retry is added. Firestore may retry transaction conflicts internally, so transaction bodies must remain side-effect-free.
- Cache notices describe last-loaded data without pretending a network detector exists. Server-only reads and contact revalidation require connectivity. Query cache is in memory and private cache keys are isolated by UID; Firestore durable offline persistence is not explicitly enabled by the app. There is no durable offline draft or confirmed-write queue.
- App configuration now has `android.versionCode: 1`, `allowBackup: false`, and blocks storage, overlay, vibration, direct-call and contacts permissions that inspected features do not use. Introspection leaves INTERNET and removal directives for those blocked permissions. Native regeneration/rebuild is required; the installed development APK was not changed.
- `eas.json`: production/store/app-bundle, remote credentials, production environment, local version source. `.easignore` preserves ignore rules and excludes generated Android/iOS projects so EAS regenerates from app.json instead of consuming local debug signing configuration.

## Exact build workflow after blockers are resolved

1. Verify EAS project ownership/linking with `npx eas-cli@latest project:info`. If unlinked, initialize/configure under the correct owner deliberately; no project ID is invented in the repository.
2. Set EXPO_PUBLIC_FIREBASE_API_KEY, AUTH_DOMAIN, PROJECT_ID, APP_ID and Google web/iOS client values as needed in the EAS **production** environment. These are bundled client identifiers, not server credentials. Do not place Admin keys/passwords there. Keep emulator mode off for release. Verify the Google Android client matches package and the release/Play signing fingerprints.
3. Inspect `npx eas-cli@latest credentials --platform android` and select the existing approved upload credentials. Do not approve creation/replacement of production keys without owner authorization. Remote credentials avoid committing a keystore or credentials.json.
4. Recheck typecheck/lint/tests and `npx expo config --type introspect --json`. Inspect `npx eas-cli@latest build:inspect --platform android --profile production --stage pre-build --output /tmp/manshaet-eas-inspect` in the correct EAS environment. Ensure native folders are regenerated, no local `.env`/credentials are uploaded, intended config is injected and only necessary permissions remain in the final merged release manifest.
5. When authorized to consume the build service and use the confirmed credentials: `npx eas-cli@latest build --platform android --profile production`. Optional local EAS build uses the same profile with `--local` and requires the native toolchain/credentials. Neither command was run here; neither uploads to Play automatically. Do not use the generated Gradle debug-signed release as proof of production readiness.
6. Inspect the actual AAB using bundletool/Play's explorer: package, name, versionCode, min/target SDK, permissions, backup behavior, signatures, 16-KB native-library compatibility, icon masking/splash/deep links and no cleartext production endpoints. Current installed version catalog specifies minSdk 24 / targetSdk 36 / compileSdk 37; that is source evidence, not artifact proof. No custom production cleartext network security exception was introduced.
